# War Card Game

A Java console card game for 2–8 players. The deck is loaded from a file,
perfect-shuffled 1–100 times, and dealt to the players. Each active player
plays their top card. The highest rank wins, with suit breaking rank ties
(Diamond, Heart, Spade, then Club). The winner adds the played cards to the
bottom of their deck. A player holding all 52 cards wins the game.

## Requirements

- JDK 11 or newer, with `java` and `javac` available on your PATH.
- Maven 3.6.3 or newer (`mvn` on your PATH), or the Maven bundled with IntelliJ IDEA.
- Git to clone the repository.
- No external Java libraries are required.

## Clone and run

```sh
git clone https://github.com/farhiyaayyub/WarCardGame-JAVA-Implementation.git
cd WarCardGame-JAVA-Implementation
mvn clean package
java -jar target/war-card-game-1.0-SNAPSHOT.jar
```

Run these commands from the repository root. The default deck is stored in
`src/main/resources/input.txt` and Maven includes it in the JAR.
An optional `resources/input.txt` in the working directory overrides the bundled deck.
The `target` folder is generated by Maven and is not committed.

## Build a portable JAR

From the repository root, run:

```sh
mvn clean package
```

You can copy `target/war-card-game-1.0-SNAPSHOT.jar` to any folder and run it with
`java -jar war-card-game-1.0-SNAPSHOT.jar`. The game uses
`resources/input.txt` in the working directory when present; otherwise it loads
the copy packaged inside the JAR.

In IntelliJ IDEA, open the Maven tool window and run **Lifecycle > package**
after changing the code or input file. Maven generates the JAR manifest automatically.

For a short demo, enter `8` players, `2` shuffles, and `NO` when asked to
play again. With the supplied input file, this finishes after 7 rounds.

## Run in IntelliJ IDEA

1. Open the cloned repository folder as a project.
2. Set the Project SDK to JDK 11 or newer.
3. Right-click `pom.xml` and select **Add as Maven Project**, then reload Maven.
4. Open `src/main/java/cardgame/Main.java` and run `main()`.
5. In the run configuration, use the repository root as the working directory.

## Where the game logic lives

`Game.java` controls the game. Its constructor prepares and deals the deck.
`start()` repeats rounds until `findChampion()` finds a player with 52 cards.
Each `playRound()` calls `drawCards()`, `findRoundWinner()`, `collectCards()`,
and `checkEliminations()`.

`Card.compareTo()` defines which card is stronger: rank first, then suit.
`Deck.perfectShuffle()` defines the shuffle algorithm. `Main.java` reads user
input and starts games, while `Console.java` contains shared output formatting.
The nested `resources/resources` folders preserve the runtime path
`resources/input.txt`: the first folder is Maven's resource root, and the second
is the folder included inside the JAR.

## Execution flow

`Main.main()` displays the welcome message and calls `Deck.loadCards()`.
It then reads the settings and creates a `Game`, which creates the players,
shuffles the deck, and deals the cards. `Game.start()` runs the rounds:
draw cards, compare them using `Card.compareTo()`, collect the played cards,
display the winner's updated deck, and check eliminations. Before each round,
the game checks whether a player holds all 52 cards. After the final result,
control returns to `Main` to ask whether to play again.

## Notes

- This variant uses suit order to break rank ties; it does not use face-down war rounds.
- Perfect shuffling is deterministic. The same input file and settings produce the same game.
- There is no round limit or repeated-state detection, so termination is not guaranteed for every setup.
- Card codes such as `H-A` remain readable if a terminal cannot display suit symbols.
  Color rendering depends on terminal support for ANSI colors.
